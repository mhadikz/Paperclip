# Privacy & security

Clipboard managers see highly sensitive data. This project treats privacy as a hard requirement.

## Principles

1. **Local-only by default** — no network calls for clipboard content
2. **No accounts / backend / analytics**
3. **AI on-device when used** — Apple Foundation Models behind availability checks
4. **Never log clipboard bodies**
5. **AI metadata is as sensitive as the original clip**
6. **User can disable all AI**
7. **Honor the ecosystem's signals** — concealed/transient pasteboard types are never recorded

## Sensitive content detection

`Domain/Services/SensitiveContentFilter.swift` detects likely:

- PEM / OpenSSH / PGP private key blocks
- JWTs (three dot-separated segments starting with `eyJ`)
- Markers such as `password=`, `api_key=`, `Authorization: Bearer`, `aws_secret_access_key`
- Known key formats: OpenAI `sk-`, Stripe `sk_live_`, GitHub `ghp_`/`github_pat_`, GitLab `glpat-`,
  Slack `xox*-`, AWS `AKIA`/`ASIA`, Google `AIza`/`ya29.`, Shopify, npm, DigitalOcean, Hugging Face, PyPI
- Card numbers: 13–19 digits in one contiguous run (spaces/dashes allowed) passing Luhn
- Opaque tokens: single 24–128 character word with ≥ 3 character classes, ≥ 15 % digits and high entropy

Explicitly **not** sensitive (false positives hurt more than storing a token locally): URLs,
emails, file paths, UUIDs, hex digests, identifiers without digits, phone numbers, dates.
Tests in `PaperclipTests/SensitiveContentTests.swift` cover both directions — extend them when
adding patterns.

### Storage policies (`SensitiveStoragePolicy`)

| Policy | Behavior |
| --- | --- |
| `neverStore` (default) | Skip capture when sensitive (if "skip likely secrets" is on) |
| `storeWithoutAI` | Store clip; never send to the model |
| `storeEncryptedPlaceholder` | Store `[redacted <kind>]` only |

The widget snapshot also drops sensitive clips.

## Pasteboard etiquette

- `org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`,
  `org.nspasteboard.AutoGeneratedType` and known password-manager types are skipped before any content is read.
- Our own writes are excluded via change-count sync, so pasting never re-records.

## AI processing rules

- Sensitive items are not processed unless `processSensitiveContent` is on
- `credentials` category marks skipped items
- Clearing AI metadata must not delete `history.json`
- Prompts never include more than the first 3,500–4,000 characters of a clip

## Logging policy

`AppLogger` uses `OSLog` with public, content-free messages. **Forbidden:** raw clip text, OCR text,
user file paths, API keys, tokens. Persistence errors log the file label and the error description only.

## Permissions

| Permission | Needed for | Without it |
| --- | --- | --- |
| Accessibility | Pressing ⌘V into the frontmost app | Choosing a clip copies it; Settings explains |
| Login Items (`SMAppService`) | Open at login | Manual launch |
| None for capture | Pasteboard polling needs no permission | — |

The app prompts for Accessibility once, on the first paste attempt with auto-paste enabled.

## Screen sharing

`hideFromScreenSharing` sets the History panel's `sharingType = .none`.

## Ignored apps

Preferences › Ignored Apps excludes bundle IDs (password managers, terminals, …).

## Data at rest

`~/Library/Application Support/Paperclip/` (JSON + media) and the app-group container (widget
snapshot with short previews plus copy text for non-sensitive text/link clips). Files are plain;
FileVault protects them at rest like the rest of the home folder. `.bak` copies and `.corrupt-*`
quarantine files carry the same sensitivity — delete them with the folder.

## URL scheme

`paperclip://open`, `paperclip://settings`, `paperclip://paste/<uuid>` (copies a clip by id, used by
the widget). Nothing can be read back through the scheme.

## Threat notes (honest)

- Any local clipboard manager can be read by other processes with sufficient privileges on the same Mac
- Accessibility permission increases power (synthetic keystrokes)
- Ad-hoc signed personal builds are for the owner's machine; distribute notarized builds only

## Checklist for AI/privacy PRs

- [ ] No new logging of content
- [ ] Capture still works with AI off
- [ ] Sensitive path covered by tests (positives and false positives)
- [ ] Docs updated if policy UX changed
